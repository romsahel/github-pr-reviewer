      Why

      The legacy-webview boot guard (#266) made the failing Outlook 2016/2019 population visible in Sentry, but the events are void of actionable metadata: no Outlook build, no platform, and no clue which customer or user is affected. We can see that boots fail, but not who needs an Outlook update or how big the problem is — verified live by the first alerts coming in (issue 7540819429).

      Summary

      The beacon now ships everything available at boot time as indexed, facetable Sentry tags: Outlook host/platform/version, locale, the affected user and their org domain. Key insight: office.js itself loads fine in the legacy webview — only our module bundle doesn't — so the guard can wait for Office readiness (raced against a 10s timeout, with synchronous URL-derived metadata as fallback) and read the authoritative diagnostics and mailbox profile before sending its single event.

      Notes

      • Tested end-to-end in Outlook web by suppressing the bundle: this event is the result — enriched tags, user, and Browser/OS facets all visible.

actionable metadata — no Outlook build, platform, or affected user.
